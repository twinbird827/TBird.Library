# TradeAnalyzer ML（段階2: LambdaRank 一次モデル）

特徴量・学習・推論を**すべて Python で完結**するバッチ。C#↔Python の境界は `trade.db`（同一 SQLite）のみ。
Python が `Signal.MlScore` に out-of-sample スコアを書き戻し、C# はそれを読むだけ（ONNX 不使用・プロセス連携なし）。

## 依存・セットアップ

[`uv`](https://docs.astral.sh/uv/) 管理（`pyproject.toml`）。`.venv/` は `_Scheduler/ml/` 内（gitignore 済・`uv sync` で再生成可）。
学習済みモデル実体は **`_Tools/TradeAnalyzer/ml/models/`**（`train.py` が `__file__` からリポジトリルートを求めて解決。
`_Tools/` は gitignore 済＝_ フォルダの削除やブランチ切替でも生存する。C# の `AppPaths.MlModelsDir` と一致）。

```bash
cd _Scheduler/ml
uv sync              # .venv 作成＋依存解決（lightgbm/optuna/pandas/numpy/scikit-learn）
```

## 実行手順（正しい順序）

段階2は**手動起動の逐次バッチ**。SQLite 書込ロック衝突を避けるため Python は **C# プロセス完全終了後**に実行する。

```bash
# 0. (C#) 段階1で ingest 済みの trade.db を用意（要 APIキー。複数年の DailyBar が必要）

# 3. (Python) OOS 検証レポート（Rank-IC / NDCG@K）

dotnet run --project .. -- backtest --is 2024 --oos 2025 --use-ml false
dotnet run --project .. -- backtest --is 2024 --oos 2025 --use-ml true
```

### 買い方の探索（#414）

`rules.py` の全ルールを月末形成・翌月末保有で評価し、事前に固定した選抜基準で候補を選ぶ。形成月は DailyBars の最古月から 13 か月後〜最新の前月で、月数で 3 等分して P1・P2・P3 にする（端数は P3）。選抜基準は (1) TX（上位 5 分位 − 全銘柄平均）の月平均が P1・P2・P3 のすべてで正、(2) LS（上位 − 下位 5 分位）も同様、(3) 全期間の TX の t 値 2.0 以上、(4) 業種内順位版でも TX が P1・P2・P3 のすべてで正（業種単位のルールは対象外）。通過したルールを 3 期間の TX の最小値の降順に並べ、月次 TX の相関が 0.7 を超える組は下位を落とし、上位 5 本を候補にする。DB は読み取り専用で開く。

`triggers.py` の全トリガーを「トリガー日の翌営業日の始値で建て、5・60・120・240 営業日持つ」前提で評価し、通過したトリガー・売りのトリガーを使った見送り/早めの売り・通過したトリガーの OR 戦略を要約する。買いのトリガーは買い、売りのトリガーは (a) 貸借銘柄の空売りとして評価し、比べる相手はトリガー日に母集団の条件を満たす全銘柄の同じ区間の等金額平均。往復コスト 0.3% を引き、空売りは貸株料（年 1.15%、逆日歩は入れない）も引く。【トレンド】のトリガーは建値から 10% 逆行したら手仕舞い、保有中の同じ銘柄への再トリガーは数えない。トリガー日の月は DailyBars の最古月から 13 か月後〜最長の保有期間の売却日が DB に収まる最後の月で、月数で 3 等分して P1・P2・P3 にする。通過の基準は件数 200 以上・30 か月以上・月平均の超過リターンが P1・P2・P3 のすべてで正・全期間の Newey-West の t 値 2.5 以上（空売りは超過リターンの符号を反転して当てる）で、各トリガーは通過した保有期間のうち P1〜P3 の最小値が最大のものを採る。通過した売りのトリガーは、通過した買いのトリガーの (b) 見送り条件と (c) 保有中の早めの売り条件として評価し、元との差の月次系列の t 値 2.5 以上・P1〜P3 のすべてで正なら採用する。OR 戦略は通過した買いのトリガーを日次で組む。DB は読み取り専用で開く。

`scan.py` は、その表で「1 指標の 5 分位」と「2 指標の分位の組み合わせ」を総当たりする。分位は形成日ごとの母集団の中の順位（同じ値は平均順位）を 0.2 刻みで切り、欠損の銘柄はその指標の条件に入れない。条件の値は、形成日ごとの「条件を満たす銘柄の超過リターンの平均」を形成日の月で平均した系列の、月をまたいだ平均と Newey-West の t 値で、足切りは件数 1,000 以上・30 か月以上。形成日ごとに超過リターン（3 つの保有期間をまとめて）を銘柄の間で並べ替えて総当たりを 200 回やり直し、足切りを通った全条件・全保有期間で偶然でも出る最大の t 値（避ける条件にはコスト前の最小の t 値）の分布を作る。候補は t 値が最大の t 値の 95% 点以上で D1・D2 の月平均がどちらも正のもので、t 値の降順に、採った候補と行の重なり（積集合 ÷ 小さいほうの件数）が 0.8 以上のものを飛ばして 5 本まで採る。避ける条件はコスト前の t 値が最小の t 値の 5% 点以下のもので（見送りは売買しないのでコストを引かない）、候補にはしない。DB は読み取り専用で開き、封印期間の価格は読まない。

`hold.py` は、同じ表で「ベースの買いルール（roa_op の順位 0.5 以上かつ pbr の順位 0.5 以下）で買ってよい銘柄を決め、その中で売る理由の無い銘柄を買い、売る理由が出るまで持ち続ける」戦略を、毎週の形成日の翌営業日の始値で売買するシミュレーションで測る（枠 50 銘柄・片道コスト 0.15%）。判定は形成日の引け後に母集団の中の順位で行い、欠損の条件は偽。売る理由のどれかが真なら売り、買う時点でどれかが真の銘柄は買わない。母集団から外れた銘柄も売る（始値が無ければ `Market.C`）。候補が空きより多いときは乱数で選び、そのときの現金を新しく買う銘柄で等分する（比率は直さない）。コストは売買した金額にだけ掛け、資産は約定日の始値（無ければ `Market.C`）で評価し、期間の終わりに持っている銘柄は清算しない。比べる相手は (1) 全銘柄の等金額（始値 → 次の約定日の始値、コストなし）・(2) 売る理由では売らない・(3) 13 週ごとの全体の入れ替え・(4) 本体の売る理由による売却と同じ件数の無作為な売り（50 回）で、本体・(2)・(3)・売る理由を 1 つずつ外した版は買う順の種 20 本の平均で要約する。月ごとの超過は、約定日から次の約定日までの区間を始まりの約定日の月に入れ、月ごとに複利でつないだ (1) との差で、期間の月を半分に分けて D1/D2（端数は D2）にする。合否は本体の (1) に対する月平均の超過が D1・D2 ともに正かつ (4) の 95% 点以上（売る理由は `hold.py` の `REASONS`）。DB は読み取り専用で開き、封印期間の価格は読まない。

## ⚠ 順序ガード（MlScore 全消去）

`signals` は date 単位の delete→insert で `MlScore=null` を再挿入するため、書き戻し済みスコアを消す。
**`signals` を回したら同期間の `train.py` を必ず再実行してから `backtest --use-ml true`** すること
（さもないと C# 側の null 検査で即エラー＝silent fallback を防ぐ意図的挙動）。
正しい運用順序は常に `signals → train → (evaluate) → backtest --use-ml`。
`RuleOptions` を変えた場合も母集団が変わるので `signals` 再生成→再学習が必要。

**段階2以降は `--use-ml false`（非ML）も `signals` 実行が前提**になった（破壊的変更）。
backtest は ML/非ML とも母集団を保存済み Signal から読む（provenance 対称化＝同一 OOS で
ML/非ML が定義上同一 picks 母集団を共有し A/B を公正化する）。OOS ウィンドウに取引日が在るのに
Signal 行が皆無なら「signals 未実行」として `InvalidOperationException` で停止する（従来の「非ML は
signals 無しでも RuleEngine 再評価で完結」する挙動は廃止）。

## 既知の制約

- **OOS 母数とサバイバーシップ**: 検証は J-Quants Light の5年データ（OOS ≈ 1.5年/72リバランス日）。
  OOS 母数が限られ Rank-IC の統計的有意性には限界（株式の Rank-IC は本来 0.02〜0.05）。加えて master は
  単一スナップショットで survivorship バイアスが残る（上場廃止/新規上場が母集団に反映されず楽観方向に偏りうる）。
  段階2の目的はパイプライン疎通＋ルール単純合算を超えうるかの一次確認。実運用精度の作り込みは段階3以降。
  実測（Light 5年, OOS 68日）: ML Rank-IC +0.036 は t=+2.17/p≒0.03 で有意（IC>0率63%）だが、
  **ML−Rule の上乗せ +0.038 は t=+1.77/p≒0.076 と5%有意には未達**＝「ルール超え」は示唆どまり。
  p値・符号検定は正規近似（標本日数が小さいほど近似は粗い）。
- **足切り後母集団のみ学習**: ML はルール `Passed` 銘柄だけを並べ替える（段階ゲート）。
- **ラベルとバックテストエグジットの非対称**: ラベルは固定 H ホライズン、バックテストは ATR ストップ/MaxHoldDays。
  ランキング学習は相対順位なので許容。実損益（バックテスト）とランキング指標（Rank-IC）は別物として読む。
